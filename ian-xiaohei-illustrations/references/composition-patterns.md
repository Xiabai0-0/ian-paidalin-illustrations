# 构图模式与原创规则

本文件是角色无关的构图引擎。角色外形、职业动作和禁忌只从 `xiaohei-ip.md` 注入；迁移 IP 时不要在这里复制人物设定。

## 基础结构类型

单张只选一种结构，不要混合多个模板。

### Workflow 流程

适合：输入 -> 处理 -> 输出、内容生产、自动化链路。

画法：用一个连续物理场景表达变化，不要画整齐方框。主角必须亲手完成中段转换。

### 系统局部

适合：信息来源、过滤器、数据库、渲染器、agent 系统的一个关键模块。

画法：只画局部和 3-5 个必要部件。主角检查、修理、替换或操作最关键的连接点。

### 前后对比

适合：混乱/有序、手动/自动、分散/收拢、模糊/清晰。

画法：让同一动作跨越左右状态，不用正式分割线。主角的取舍或修正必须造成右侧结果。

### 角色状态

适合：用户痛点、创作者状态、信息焦虑、卡住到跑起来。

画法：2-4 个连续姿势，每个姿势只保留一个动作和一个短标签。避免表情包格子。

### 概念隐喻

适合：信任、价值、内容复利、判断、承重、沉淀等抽象观点。

画法：发明一个低科技、物理关系成立的怪物件。主角通过职业动作让抽象关系变得可见。

### 方法分层

适合：方法论框架、系统层级、能力栈、内容系统分层。

画法：使用不规则纸砖、抽屉、支架或工具层，不用金字塔。主角正在搭建、排序或校验其中一层。

### 地图路线

适合：从想法到上线、用户路径、内容承接路径、学习路线。

画法：一条弯曲但清楚的物理路线，最多 4-5 个节点。主角在途中检查、修正或选择，而不是沿线摆拍。

### 小漫画分镜

适合：失败到成功、真实过程、吐槽、使用前后变化。

画法：2-4 个开放场景，格线可以不完整。每格一个动作，角色身份和服装必须一致。

## 原创隐喻生成法

### 四步

1. 把抽象概念换成一个可见变化：卡住、漏掉、变重、分开、沉淀、折叠、失衡、对齐、支撑、回流。
2. 选择一个低科技物件：纸箱、抽屉、旧机器、秤、门、井、梯子、水管、闸门、转盘、工作台、支架、胶带路。
3. 从 `xiaohei-ip.md` 选择一个符合角色职业的动作，让主角亲手造成变化。
4. 删除一切不影响核心判断的节点、箭头、标签和装饰。

只选 1-2 个主要物件、一个核心动作和 2-6 个短标签。

## 动作注入规则

- 不在本文件维护固定角色动作池。
- 动作必须来自 `xiaohei-ip.md` 的“动作语法”和“场景映射”。
- 同一文章的多张图不得重复同一主物件与同一动作组合。
- 如果去掉主角后构图仍完全成立，动作注入失败：让角色亲手造成输入、转换、取舍、修复或结果。
- 如果动作只剩“站着指向”，改成拆、写、画、贴、圈、剪、校验、排序、搭建、复盘或目标 IP 文件定义的其他职业动作。

## 反复刻规则

`assets/examples/` 只用于校准角色一致性、线条密度、留白和颜色克制，不是构图模板。

除非用户明确要求复刻，不得直接复用校准样图的：

- 工作台的三阶段纸张加工。
- 断裂齿轮的逻辑维修。
- 左乱右清的草稿删除。
- 四姿势的卡住到想通。
- 证据板支撑观点平台。
- 事实/洞察/表达的纸砖搭层。
- 胶带路线与转向牌。
- 初稿/修改/完成三格分镜。

同类主题必须换主物件或动作。例如“建立信任”可以是校准一台失真的秤、修补一张漏水的证明纸，或把散落凭据装进一个承重夹具；不要默认画证据平台。
